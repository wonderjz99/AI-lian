## 1. 产品目标

网页显示名为 **AI 经纬**，副标题为 **中国 AI 公司关系地图**。

以中国大陆及香港公司为范围，将代表性 AI 公司放在产业分层地图上，展示有出处的产业与资本关系。用户可以选择任意两家公司，查看双方关系、共同新闻以及各自动态。

第一用户是项目发起人，以个人产业研究为主；其他人也可以通过链接直接浏览。

第一版解决三个问题：

1. 一家公司主要处在哪个 AI 产业环节？
2. 两家公司有什么已经确认的业务或资本关系，依据是什么？
3. 收集的资料中，两家公司共同发生了什么，各自有什么动态？

## 3. 产业分层

地图从上到下固定为以下五层。

| 顺序 | 分层 | 收录的主要能力 |
| --- | --- | --- |
| 1 | 芯片与硬件 | 芯片、存储、服务器等 |
| 2 | 算力与云基础设施 | 数据中心、算力服务、云平台 |
| 3 | 基础模型 | 通用或专用基础模型开发 |
| 4 | 开发工具与平台 | 模型部署、数据服务、开发平台等 |
| 5 | 应用与行业解决方案 | 面向个人或企业的 AI 产品与服务 |

一个公司只保留一个节点，放在其主要角色所在层，其他业务角色用标签表示。主要角色是编辑分类，不代表公司只经营这一项业务。

角色标签可以用于查看参与该环节的公司，不复制公司节点，也不改变其唯一身份。产品、模型和品牌放在公司详情中，第一版不作为独立图节点。

公司在层内的位置优先保证标签清晰、关系易读。纵向位置表达主要产业角色；每条线自己的标签与箭头表达关系，不凭上下位置推断供货或控制方向。

## 4. 连线的含义

连线表示有明确出处的公司关系。共同出现在报道中，不自动生成正式关系线。

| 类型 | 所属视图 | 定义 | 方向 |
| --- | --- | --- | --- |
| 控股 / 子公司 | 资本关系 | 有依据确认 A 控制 B；持股比例与控制关系分别记录 | 控制方 → 被控制方 |
| 参股投资 | 资本关系 | 有依据确认 A 对 B 的参股投资，与控股关系区分 | 投资方 → 被投资方 |
| 供应 / 服务提供 | 产业关系 | A 向 B 提供具体硬件、算力、模型或其他服务 | 提供方 → 使用方 |
| 战略合作 | 产业关系 | 双方明确宣布合作，记录合作事项 | 无方向，或明确的双向标识 |

规则：

- 同一对公司可以有多种关系；不得将所有内容概括为一条“有关联”。
- 不根据持股比例独自推断控制权，不根据业务类别推断客户或供应商。
- 区分已完成、进行中、已宣布但未完成、已结束等状态；拟议交易不能直接画成已完成的控股关系。
- 来源无法支持明确类别的内容，保留为新闻，不进入正式关系图。
- 每条关系都有简短说明、来源链接、确认日期和状态；比例、金额等没有资料时留空。
- 同类关系可以附多条证据或事件，不因重复报道创建重复连线。
- 不自动从 A→B、B→C 推断 A→C 存在同类关系。
- 线型、颜色与标签共同区分类型，不能仅依赖颜色。

产业关系视图展示供应 / 服务与战略合作；资本关系视图展示控股 / 子公司与参股投资。各视图内可筛选相应关系类型。两种视图都保留产业分层和公司位置。

## 5. 页面与交互

### 5.1 桌面布局

- 顶部：项目名、副标题、公司搜索、视图切换、节点大小模式、选中的公司标签和重置入口。
- 主区：五层地图，支持拖动画布与缩放。
- 右侧：使用提示、单公司详情、双公司面板或关系详情。
- 图例 / 页面说明：关系类型、箭头含义、市值模式说明、资料截止日。

默认采用浅色背景，参考 MAPD 的分层展示形式。第一版不要求增加深色主题。

### 5.2 首次打开

显示全部公司、五层结构和浅色的产业关系线，默认产业关系视图、等大节点。右侧提示：点击公司查看详情，再点击另一家公司比较关系与新闻。

选中公司后，高亮它的相关节点与连线，其余内容淡化。选择和视图切换不应导致整张地图无意义地重新排列。

### 5.3 公司选择状态

| 当前状态 | 操作 | 结果 |
| --- | --- | --- |
| 无选择 | 点击 A | 选中 A，显示 A 的详情与动态 |
| 仅 A | 点击 B | 选中 A、B，进入双公司面板 |
| 已选 A、B | 点击第三家 C | 保留 A，用 C 替换 B |
| 已选公司 | 取消一个公司标签 | 剩余公司进入单公司状态 |
| 任意状态 | 重置 | 清除选择并恢复首次打开的地图状态 |

顶部持续显示选择结果，不要求 Ctrl、Shift 等组合键。搜索结果使用同一套选择规则；搜索覆盖中英文名称和已整理的别名。

只有一个剩余公司时，将其视为下一次双选的第一家公司。切换产业 / 资本视图或节点大小模式时，保留已选公司。

### 5.4 单公司详情

展示公司名称、简短介绍、主要层级、其他角色、主要产品 / 模型、已收录关系和固定资料中的新闻动态。市值或融资估值必须带日期、币种和来源，缺失时明确说明。

### 5.5 双公司面板

面板标题为“A × B”，默认展示双方全部已收录关系，并用类型与状态说明。即使当前地图只显示产业关系，也不能让用户误认为没有资本关系；面板中的关系类型标识负责说明这种差别。

新闻分两个标签页：

1. **共同报道**：默认页，展示事件或报道中实质涉及双方的内容。
2. **各自动态**：分别展示 A 与 B 的新闻，明确区分所属公司。

地图高亮两家公司、当前视图中的直接关系和各自直接关联；第一版不增加自动最短路径分析。

无已知连线也允许查询。分别呈现这些状态：

- “当前资料未收录两家公司的已确认关系”。
- “当前资料范围内未找到共同报道”，提供各自动态入口。
- 有共同报道但没有关系线时，明确说明共同报道不等于已经确认的业务或资本关系。

无连线、无报道均不等于现实中不存在关系或事件。

### 5.6 点击连线

打开对应关系的详情，展示关系类别、方向、事项、状态、日期、持股比例或金额（如有）以及支持该关系的报道 / 公告。

若两端公司尚未选中，将它们设为当前双选对象；可以切回双公司新闻面板。多种关系必须能分别查看，不用一个含糊标签覆盖。

### 5.7 手机

2026-10-09 最新决定：先完成桌面网页与 GitHub Pages 发布，手机开发、优化与验收暂缓；保留已有响应式界面。以下手机能力作为后续目标，不作为当前发布前置要求。

支持公司搜索、缩放、选择公司、切换视图和阅读新闻。详情使用底部抽屉，选中结果仍可查看和取消。手机不要求同时展示整张地图与全部侧栏内容。

## 6. 新闻与固定资料

2026-10-08 实施补充：第一版先使用少量有代表性的真实新闻验证地图、选择与阅读效果，不以新闻数量或逐家公司新闻覆盖为验收目标。可靠信息源与可选 API 记录到 `docs/data-sources.md`，供后续更新评估，当前不增加自动抓取系统。

资料截止日是在实际完成首批整理时确定的数据日期，不直接使用本文整理日期。所有页面显示“资料截至 YYYY-MM-DD”，新闻按原始发布时间倒序排列。

新闻以截止日前六个月为主；更早且解释当前关系必需的公告可以保留，并标注为历史依据。

### 6.1 事件卡片

同一事件的多篇报道合并为一张卡片，包含：

- 事件标题。
- 简短中文摘要，忠实于来源。
- 事件日期（已知时）与报道发布时间。
- 涉及公司。
- 来源名称与原文链接。
- 展开查看不同报道的入口。

同一对公司在不同日期发生的不同事项，不能仅因公司相同而合并。文章更新或转载也不能被误认为新发生的业务事件。

共同报道应实质涉及两家公司；泛泛盘点中偶然提到两家名称，不能据此推导合作。第一版使用整理好的摘要，不在浏览器中调用模型，不额外生成 AI 分析结论。

新闻展示摘要、必要证据片段和原文链接；不以全文转载为默认形式。

### 6.2 收集与校对

关系依据优先公司公告、官方博客、投资者关系资料等；新闻可补充有明确来源的媒体报道。每条正式关系都应能追溯到具体证据。

先建立候选公司名单，再整理公司身份与别名、已确认关系和新闻。出现证据冲突时保留出处，不将未解决的判断写成确定事实。

## 7. 节点大小与市值

默认所有公司节点等大。市值模式是辅助比较方式，不代表 AI 能力、AI 业务价值或产业重要性。

| 数据情况 | 展示方式 |
| --- | --- |
| 有可比上市市值 | 依统一映射规则显示大小，详情给出原始数值与来源 |
| 没有可比市值 | 固定大小、虚线外圈，标注“无可比市值” |
| 有未上市融资估值 | 仅在详情单独展示估值、融资日期及来源，不混入市值映射 |

市值使用统一快照日期与人民币口径，保存原币种、原始值和转换依据。多地上市公司只对应一个公司节点，不把多个渠道提供的公司总市值直接相加。母子公司的节点市值也不加总为地图中的“集团总价值”。

用圆面积映射数值，不让半径与市值直接成正比。如果为可读性采用分档、上下限或压缩映射，图例明确说明；不声称圆面积仍严格成比例。节点标签与点击区域需保持可用，悬浮或详情提供精确数值。

## 8. 实现建议

### 8.1 架构

第一版采用纯静态前端与本地结构化数据，无运行时后端、数据库、登录服务或模型调用。

```text
资料整理与校对
      ↓
结构化数据文件 → 数据校验 → 静态构建与发布
                                  ↓
                     公司地图 / 关系查询 / 新闻面板
```

建议技术组合：

- Vite + React + TypeScript：页面与选择状态。
- Cytoscape.js：图谱渲染、缩放、选择与高亮。
- 固定分层坐标或约束布局：保证产业层级与切换稳定。
- JSON 数据 + 构建前校验：维护公司、关系、事件、报道和快照信息。

这些是实现建议，不要求在规格整理阶段安装依赖或创建应用。具体布局算法以分层可读性和实测结果为准。

### 8.2 建议的数据文件

| 文件 | 内容 |
| --- | --- |
| companies.json | 公司唯一 ID、中英文名、别名、主要层、其他角色、介绍、产品、市值 / 估值资料 |
| relationships.json | 起终点公司、关系类型、说明、状态、有效日期、证据、比例 / 金额（如有） |
| events.json | 事件 ID、标题、摘要、日期、参与公司、关联报道 |
| articles.json | 报道 ID、标题、媒体、发布时间、原文 URL、必要证据片段 |
| metadata.json | 数据版本、截止日、新闻时间窗口、市值日期、币种转换依据、覆盖说明 |

公司、关系、事件与报道各自有稳定 ID。一次事件可以关联多篇报道；一条长期关系可以关联多个事件与证据。公司身份与股票代码分别记录，不能把每个上市代码当成一家新公司。

中文摘要、分类和主要角色均随资料预先整理，不在用户点击时生成。

## 9. 验收标准

### 内容

- 收录 30–40 家公司，五层均有合理覆盖，分类理由可说明。
- 公司无重复身份；多角色公司不会在不同层复制节点。
- 所有正式连线有类型、方向规则、状态、确认日期和来源。
- 所有新闻卡片有日期、中文摘要及可查看的原文链接。
- 同一事件的重复报道合并，不同事件不误合并。
- 截止日、历史依据与市值快照口径可见，无虚构数据用于填补空白。

### 交互

- 搜索中英文名与别名能够定位并选择公司。
- 首次进入为五层全图、浅色产业线、等大节点与使用提示。
- 单选、双选、第三家替换第二家、取消选择和重置行为符合规格。
- 产业 / 资本切换后选择保留，显示正确关系类型，公司位置保持稳定。
- 双公司共同报道和各自动态分别可查；无连线仍可双选。
- 无关系与无报道显示不同提示，不暗示现实中绝对不存在关系。
- 点击连线能查看该条关系的具体证据。
- 市值模式有图例，无可比市值节点采用指定标识。
- 桌面标签可读，能够完成搜索、选择、缩放和阅读；手机验收暂缓。

### 工程

- 可以在本地启动、构建，并作为静态网站部署。
- 无运行时 API 密钥、数据库或模型服务依赖。
- 数据校验覆盖：重复 ID、无效公司引用、关系自连、未知关系类型、日期格式、缺失来源和数值口径缺失。
- 未知数值用缺失值表示，不用 0 代替。
- 数据与代码可共同保存版本；变更资料后可重新构建。
